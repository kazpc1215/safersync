# safersync

`rsync` の安全なラッパー。**コピー → 照合** をワンストップで行い、進捗と残り時間を表示します。
撮影日時などのメタデータを保持したままコピーします。

- **データを削除しません。** 転送先の余分なファイルも、転送元のファイルも消しません
- **設定ファイルはありません。** すべてコマンドライン引数で指定します

## 3分で試す

```sh
# 1) コマンドを置く（~/.local/bin に PATH が通っていること）
ln -sfn ~/safersync/bin/safersync ~/.local/bin/safersync

# 2) HDD を接続して、状態を確認する
safersync --status

# 3) コピーする（例: ムービーの 写真フォルダ → HDD の 写真フォルダ）
safersync ~/写真 /Volumes/HDD/写真
```

コピー元とコピー先は**どちらもフォルダのパス**で指定します。`~/写真` の中身が
`/Volumes/HDD/写真` の中へ入ります（無ければフォルダは作られます）。

### こう表示されれば成功です

```
▶ /Users/me/写真 → /Volumes/HDD/写真
    コピーするファイル: 120 件（12.3 GB）
✓ コピー完了（120 ファイル / 12.3 GB / 2分10秒）
    コピー元 120 ファイル / 12.3 GB、転送先 120 ファイル / 12.3 GB
✓ 照合 OK（コピー元の全ファイルが転送先に存在）

✓ すべて完了（120 ファイル / 12.3 GB / 2分10秒）
```

2回目以降は、すでにコピー済みのファイルを調べて**足りない分だけ**コピーします。

```
▶ /Users/me/写真 → /Volumes/HDD/写真
✓ 転送するものはありません（すべて最新です）
    コピー元 120 ファイル / 12.3 GB、転送先 120 ファイル / 12.3 GB
✓ 照合 OK（コピー元の全ファイルが転送先に存在）

✓ すべて完了（新しくコピーしたファイルはありません）
```

## 使い方

```sh
safersync [オプション] <コピー元> <コピー先>
```

- **コピー元** … コピーしたいフォルダ（1つ）
- **コピー先** … 保存先のフォルダ（1つ）。コピー元の中身がこの中へ入ります。無ければ作られます

`--from` / `--to` でも指定でき、順序は自由です（`safersync --to DIR SRCDIR` も可）。

```sh
safersync ~/写真 /Volumes/HDD/写真          # 位置引数2つ
safersync --from ~/写真 --to /Volumes/HDD/写真
safersync --to /Volumes/HDD/写真 ~/写真     # 順序は自由
```

### 例

```sh
# HDD の 写真フォルダへコピー＆照合
safersync ~/写真 /Volumes/HDD/写真

# HDD 内の下位フォルダも自由に指定できる（無ければ作られる）
safersync ~/書類 /Volumes/HDD/backup/書類

# 何がコピーされるか先に見る（実際にはコピーしない）
safersync ~/写真 /Volumes/HDD/写真 -n

# コピーせず、照合だけ行う
safersync ~/写真 /Volumes/HDD/写真 --verify-only

# 追加で除外する / 接続状態を確認する
safersync ~/書類 /Volumes/HDD/書類 --exclude '*.tmp'
safersync --status
```

複数のフォルダをコピーするときは、回数を分けて実行してください。

```sh
safersync ~/写真 /Volumes/HDD/写真
safersync ~/書類     /Volumes/HDD/書類
```

> **末尾の `/` は付けても付けなくても同じです。** どちらの書き方でも「コピー元の中身が
> コピー先の中へ」入ります（ツールが内部でそろえます）。素の `rsync` は `SRC` と `SRC/` で
> 意味が変わり、うっかりフォルダが1段深くなることがありますが、このツールでは起きません。

## 出力の読み方

| 表示 | 意味 |
|---|---|
| `▶ コピー元 → コピー先` | これから処理する対象 |
| `コピーするファイル: N 件（サイズ）` | この回で実際に転送する量（差分） |
| `✓ コピー完了（N ファイル / サイズ / 時間）` | コピーの結果 |
| `✓ 転送するものはありません（すべて最新です）` | 差分ゼロ。何もする必要がない |
| `✓ 照合 OK（コピー元の全ファイルが転送先に存在）` | 照合に成功 |
| `✗ 差分が見つかりました` | 未転送・不一致のファイルがある（コピーを実行してください） |
| `! 転送先には N 件多いファイルがあります（削除しません）` | 正常。転送先の余分はそのまま残す |
| `! コピー先がボリュームの直下です` | フォルダ名を書き忘れていないか確認（下記） |
| `✓ すべて完了（N ファイル / サイズ / 時間）` | 全体の結果 |

> **コピー先はフォルダ名まで書いてください。** `safersync ~/書類 /Volumes/HDD` のように
> ボリュームの直下を指定すると、書類の中身が HDD の直下に散らばります（削除はしません）。
> その場合は警告が出ます。`/Volumes/HDD/書類` のように書くのが基本です。

進捗表示（ターミナルで実行したときだけ出ます）:

```
  [████████░░░░░░░░░░░░░░░░]  33%  4.1 GB / 12.3 GB  92.4 MB/s  残り 約 24分
```

`-n`（dry-run）のときは、コピーされるファイルの一覧を先頭 20 件まで表示します。

```
    コピーするファイル: 27 件（1.2 KB） ※dry-run のため実際にはコピーしません
    >f+++++++ new1.mp4
    >f........ a1.mp4
    …（他 7 件）
    （記号: > 新規/更新, f ファイル, + 新規作成, s サイズ, t 時刻）
```

## 注意: これはバックアップではありません

- このツールは「HDD に控えを取って、Mac の空き容量を増やす」ためのものです。
  **HDD 1 台だけにコピーしても、その HDD が壊れれば失われます。**
  大切なデータは 2 つ目のコピー（別の HDD・クラウドなど）も用意してください。
- **Mac 側を削除する前に、必ず「照合 OK」を確認してください。**
- 中断しても次回は続きからコピーできますが、同じ HDD を抜き差しする前に
  コピーが終わっていることを確認してください。

## オプション

| オプション | 説明 |
|---|---|
| `-f`, `--from DIR` | コピー元（位置引数と同じ。順序は自由） |
| `-t`, `--to DIR` | コピー先（位置引数と同じ。順序は自由） |
| `--mount-root DIR` | 外付けボリュームの基点（既定: `/Volumes`。Linux なら `/media/ユーザー名` など）。未マウント検出に使う |
| `-x`, `--exclude PAT` | 追加で除外するパターン（複数可。例: `'*.tmp'`） |
| `--fat` | コピー先が exFAT/FAT（**既定**。属性差を比較しない） |
| `--apfs` | コピー先が APFS/HFS+（属性も保持・比較する） |
| `-n`, `--dry-run` | 実際にはコピーせず、対象を確認する |
| `--verify-only` | コピーせず照合のみ行う |
| `--no-verify` | コピー後の自動照合を行わない |
| `-c`, `--checksum` | 内容のハッシュで照合（厳密だが遅い） |
| `--ignore-space-check` | 空き容量が足りなくても中止せず続行する |
| `-v`, `--stats` | rsync の詳細な統計を表示する（既定は非表示） |
| `--progress` / `--no-progress` | 進捗表示を強制 ON / OFF |
| `--no-caffeinate` | スリープ防止（`caffeinate`）を使わない |
| `--status` | マウント中のボリュームと空き容量を表示 |
| `-h`, `--help` / `-V`, `--version` | ヘルプ / バージョン |

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | エラー（引数の誤り、コピー元が無い、rsync の失敗など） |
| 2 | コピー先のボリュームが未マウント |
| 3 | 空き容量が足りない（開始前に中止） |
| 130 | `Ctrl-C` で中断 |

## つまずいたときは

| メッセージ / 症状 | 対処 |
|---|---|
| `コピー元を指定してください` / `コピー先を指定してください`（1） | フォルダのパスを2つ（コピー元・コピー先）指定します |
| `引数が多すぎます`（1） | 1回の実行でコピーできるのは1組だけです。分けて実行してください |
| `コピー先のボリュームがマウントされていません`（2） | HDD を接続し、`safersync --status` で状態を確認する |
| `空き容量が足りません`（3） | 不要なファイルを削除する。または `--ignore-space-check` を付けて続行（途中で失敗します） |
| `差分が見つかりました` | 未転送のファイルがあります。`--verify-only` を外してコピーを実行してください |
| `転送先には N 件多いファイルがあります` | 正常です（転送先の余分なファイルは削除しません） |
| `コピー先がボリュームの直下です` | フォルダ名まで指定し忘れていないか確認（削除はしませんが散らばります） |
| 途中で止めた | 次回は続きからコピーします（`--partial` で中断ファイルも再開） |
| 進捗が出ない | パイプやログへの出力では自動でオフになります。`--progress` で強制できます |

## コピーの考え方

- **転送先に無いファイルだけコピー**します。すでにあるファイルは、サイズと更新日時が
  同じならスキップされます（差分コピー）。
- **転送元で削除したファイルは、転送先に残ります**（勝手に消しません）。
  HDD に退避してから Mac 側を削除して空き容量を増やす、という使い方に向いています。
- 転送先に余分なファイルがあっても**エラーにしません**。
- **照合は「コピー元の全ファイルが転送先に存在するか」**を確認します。転送先の余分は許容します。
  ディレクトリの時刻だけの違いは（OS 側で合わせられないことがあるため）判定に含めません。
- 開始前に**空き容量を確認**し、足りなければコピーを始めません（`--ignore-space-check` で無効化）。

# 開発者向け

## 設計方針

- **削除機能を持たない**（`--delete` / `--delete-local` / `--mirror` は意図的に非搭載）
- **設定ファイルを持たない**（コピー元・コピー先はすべて引数で、パスを明示する）
- コピー先が基点（既定 `/Volumes`）の下なら、**実マウントされているか**をマウントテーブルで
  確認し、未マウントなら中断する（終了コード 2）。基点の外（`~/` や `/tmp`）は判定しない
- コピー前に rsync の dry-run で差分を数え、件数・容量の表示と空き容量チェックに使う
- 照合の合否は**ファイルの欠落・内容の違い**で決める。**ディレクトリの属性・時刻だけの
  違い（`.d…`）は無視**する（exFAT のボリューム直下は時刻が 1970 年で固定され、
  rsync でも変更できないため）

## 動作環境と移植性

macOS / bash 3.2 以上 / `rsync`（macOS 標準の rsync・openrsync で動作確認済み）

環境によって異なる部分は、自動判定またはオプション／環境変数で切り替えられます。

| 項目 | macOS | それ以外 |
|---|---|---|
| ファイルサイズの取得 | `stat -f '%z'` | `stat -c '%s'`（**起動時に自動判定**） |
| ボリュームの基点 | `/Volumes` | `--mount-root DIR` または `SAFERSYNC_MOUNT_ROOT`（例: `/media/ユーザー名`）。未マウント検出に使う |
| ログの場所 | `~/Library/Logs/safersync` | `XDG_STATE_HOME` があれば `$XDG_STATE_HOME/safersync`、無ければ `~/.local/share/safersync`（`SAFERSYNC_LOG_DIR` で直接指定も可） |
| スリープ防止 | `caffeinate` | コマンドが無ければ自動で省略 |

- コピーと照合の本体（rsync の呼び出し方・差分判定）は共通です。
- コピー元・コピー先はどちらもパスで直接指定するので、どの環境でもそのまま使えます。

## exFAT 対応

- exFAT はパーミッション・所有権を保存できず時刻にも丸め誤差が出ます。そのためコピーと照合は
  `-rlt --modify-window=2` を使い、属性差による誤検知を防いでいます（既定）。
- **exFAT のボリューム直下（マウントポイント）の時刻は 1970 年で固定**され、rsync でも
  変更できません。そのため照合ではディレクトリの時刻だけの違いを無視します。
- macOS が exFAT 上に後から作る `._*`（AppleDouble）は、ファイル数・サイズの集計から除外します。
- コピー先が APFS / HFS+ の場合は `--apfs` を付けると `-a`（属性も保持）になります。

## テスト

テストは [bats-core](https://github.com/bats-core/bats-core) で書かれています（`test/`）。

```sh
brew install bats-core   # 初回のみ
bats test/               # すべて実行
bats test/safersync.bats # このファイルだけ
```

- **実データには触れません。** 作業は一時フォルダと、テストが作成する exFAT ディスクイメージ内だけで完結します。
- exFAT のテストは、`hdiutil` が無い環境や、同名ボリュームが既にある場合は安全のため**スキップ**されます。
- `shellcheck` があれば静的チェック（`-S warning`）も実行されます。
